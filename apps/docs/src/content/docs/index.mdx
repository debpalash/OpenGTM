<section class="lp-section lp-bill">
  <div class="lp-section__head">
    <p class="lp-kicker">Before you run</p>
    <h2>The bill, itemised, before a single row executes.</h2>
    <p>
      Every workbook has an estimate endpoint. It multiplies rows by every paid
      provider in each column's chain for the worst case, and by the cheapest
      paid provider for the best case. Free providers never appear on it. Set a
      ceiling and the planner drops paid providers from every chain the moment
      it is reached.
    </p>
    <a class="lp-link" href="/concepts/spend/">How spend transparency works<Icon name="right-arrow" /></a>
  </div>

<div class="lp-code">

```json title="GET /api/workbooks/wb_7f3a/run/estimate"
{
  "rows": 50,
  "worst_usd": 6.00,
  "best_usd": 1.00,
  "breakdown": [
    { "column": "Email",
      "paid_providers": ["hunter_io", "apollo_io", "snovio", "prospeo"],
      "worst_usd": 6.00, "best_usd": 1.00 }
  ],
  "note": "worst = every paid provider tried per row; best = cheapest paid hit first."
}
```

<section class="lp-section">
  <div class="lp-section__head lp-section__head--center">
    <p class="lp-kicker">How a workbook runs</p>
    <h2>Four kinds of column. One durable queue.</h2>
  </div>
  <ol class="lp-flow">
    <li>
      <span class="lp-flow__n">01</span>
      <h3>Source</h3>
      <p>An ideal-customer-profile query fans out over ~90 directories, review sites, registries and job boards. Runs page, checkpoint and resume; every row keeps its provider record id, so a re-run updates instead of duplicating.</p>
      <a href="/guides/sourcing/">Sourcing</a>
    </li>
    <li>
      <span class="lp-flow__n">02</span>
      <h3>Enrich</h3>
      <p>A waterfall tries providers until one answers confidently. Free scrapers and open data go first; paid vendors on your own keys go last, reordered by measured hit-rate per dollar.</p>
      <a href="/concepts/waterfalls/">Waterfalls and the planner</a>
    </li>
    <li>
      <span class="lp-flow__n">03</span>
      <h3>Research</h3>
      <p>A bounded agent searches and fetches behind the SSRF guard, answers a question per row, and cites only URLs it actually loaded. Agent columns choose their own tools inside a step and dollar budget and leave a trace.</p>
      <a href="/guides/research-and-agent-columns/">Research and agent columns</a>
    </li>
    <li>
      <span class="lp-flow__n">04</span>
      <h3>Push</h3>
      <p>Output columns run once per row after enrichment: HubSpot, Salesforce, Google Sheets, Airtable, a webhook, or an email sequence. Idempotent by default.</p>
      <a href="/guides/outputs/">Outputs</a>
    </li>
  </ol>
  <p class="lp-types" aria-label="Column types">
    <span>lead_field</span><span>source</span><span>enrichment</span><span>waterfall</span><span>ai_formula</span><span>research</span><span>agent</span><span>http</span><span>formula</span><span>conditional</span><span>output</span>
  </p>

    <p class="lp-kicker">Promises, in writing</p>
    <h2>Structural, not marketing.</h2>
    <p>A seat-priced, credit-metered incumbent cannot match these without undoing its own business model.</p>
  </div>
  <dl>
    <div><dt>The API is never plan-gated.</dt><dd>REST, webhooks, MCP tools, the n8n node and the Chrome extension are first-class on every install. Automating OpenGTM is a use case, not an upsell.</dd></div>
    <div><dt>Your keys, vendor price, zero markup.</dt><dd>You pay LLM and enrichment vendors directly. Any future managed-key option bills at cost plus one disclosed flat fee, never per credit.</dd></div>
    <div><dt>The bill before the run, always.</dt><dd>The estimate, the ceiling and the per-provider cost ledger are core features on every tier there will ever be.</dd></div>
    <div><dt>Self-host is complete, forever.</dt><dd>No feature is held back to force a cloud upgrade. If a paid line ever exists it will be governance: SSO, audit export, support.</dd></div>
  </dl>

      <li><b class="lp-num">~90</b> sourcing connectors with durable, resumable runs</li>

      <li><b class="lp-num">19</b> validated workbook recipes in the template gallery</li>
      <li><b class="lp-num">189</b> documented REST endpoints, generated from the running app</li>
    </ul>
  </div>
  <div class="lp-stack__col">
    <p class="lp-kicker">How it is built</p>
    <ul class="lp-facts">
      <li>FastAPI and SQLAlchemy 2 on <strong>PostgreSQL</strong> with fail-closed row-level security per workspace</li>
      <li>A PostgreSQL job queue; workers claim with <code>FOR UPDATE SKIP LOCKED</code> and commit each page with its cursor</li>
      <li>Every user-supplied URL passes an SSRF guard that rejects private, loopback and metadata ranges and re-checks redirects</li>
      <li>Per-workspace secrets encrypted at rest; tokens stored hashed and shown once</li>
      <li>React 19 and Vite front end; MCP server; n8n node; Chrome capture extension</li>
    </ul>
  </div>
