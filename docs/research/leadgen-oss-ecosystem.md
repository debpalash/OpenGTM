## 7. Architecture Patterns Deep-Dive

### Pattern A: Waterfall Enrichment (YALC/Clay)
```
For each field (email, phone, etc.):
  Provider Chain: [Hunter.io] → [Clearbit] → [Pattern Gen] → [Web Scrape]
  Stop at first successful result
  Track which provider succeeded (for quality metrics)
```
> **Yupcha Gap**: We try one approach per field. Should chain multiple providers with fallback.

### Pattern B: LangGraph Agent Pipeline (kaymen99)
```
                    ┌─────────────┐
                    │ Orchestrator │
                    └──────┬──────┘
         ┌─────────┬───────┼───────┬──────────┐
    ┌────▼───┐ ┌───▼───┐ ┌▼─────┐ ┌▼────────┐ ┌▼─────┐
    │Research│ │Qualify│ │Score │ │Personalize│ │Outreach│
    │ Agent  │ │ Agent │ │Agent │ │  Agent   │ │ Agent │
    └────────┘ └───────┘ └──────┘ └──────────┘ └───────┘
```
> **Yupcha Gap**: Our pipeline is sequential functions, not independent agents. Agents allow parallelism + retry per stage.

### Pattern C: Browser-Use AI (contact-use)
```
AI Agent + Real Browser → navigate to company website
→ find contact page → extract email/phone → fill contact form
→ send LinkedIn connection request → compose cold email
```
> **Yupcha Gap**: We scrape HTML. Browser-use AI can handle JS-heavy sites and even interact with forms.

### Pattern D: MCP-First (LeadMagic, LinkedIn MCP)
```
AI Assistant (Claude/GPT) → MCP Server → LinkedIn API / Email API / CRM API
Users interact via natural language, tools do the work
```
> **Yupcha Gap**: We have CopilotKit chat. MCP servers would make our tools available to any AI client.

## 9. Key Technical Insights from Top Repos

### Email Discovery (from email-sleuth + mailscout)
```python
# Best practice: 13+ patterns, ordered by probability
patterns = [
    f"{first}.{last}@{domain}",      # john.doe@company.com (most common)
    f"{first[0]}{last}@{domain}",     # jdoe@company.com
    f"{first}@{domain}",              # john@company.com
    f"{first}{last}@{domain}",        # johndoe@company.com
    f"{first}_{last}@{domain}",       # john_doe@company.com
    f"{first[0]}.{last}@{domain}",    # j.doe@company.com
    f"{last}.{first}@{domain}",       # doe.john@company.com
    f"{last}{first[0]}@{domain}",     # doej@company.com
    f"{first}{last[0]}@{domain}",     # johnd@company.com
    f"{first[0]}{last[0]}@{domain}",  # jd@company.com
    ...
]
# Then: MX check → SMTP RCPT TO verify → catch-all detection
```
