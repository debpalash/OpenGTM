# Clay Alternatives — OSS Research Report (What Yupcha Can Steal)

> **Search:** GitHub `gh search repos "clay alternative"` (only 6 direct hits), broadened/merged with `clay.com alternative`, `clay enrichment`, `clay clone`, `claygent`, `enrichment waterfall`, `GTM engine`, `lead/company/people enrichment`, `sales intelligence`, `prospecting tool`.
> **Found:** 385 unique repos across all queries. **Cloned:** 149 (shallow, top-150 by relevance×stars). **Skipped:** 1 clone timeout + 1 archived + the long 0-star tail (deduped into the appendix).
> **Date:** 2026-06-07. Clones live in `reference/research/clay-alternatives/<owner>__<repo>/` (not committed).

The "clay alternative" niche is dominated by two clusters: (1) **enrichment-waterfall engines** (the actual Clay innovation — cheap→expensive provider cascades with short-circuit-on-hit) and (2) **GTM-skill packs for Claude Code** (ICP/signal/scoring/outreach prompt libraries). The waterfall engines are the highest-value ingestion targets for Yupcha's enrichment subsystem; the skill packs are gold for the copilot and AI columns. A handful of repos additionally ship reusable scrapers, tech-stack detectors, SMTP verifiers, signal sources, and table-UI patterns.

## 2. Top ingestion opportunities (highest value first)

1. **Adopt the effective-cost waterfall core** → *enrichment waterfall*.
   Source: `masteranime/enrichment-kit/src/waterfall/index.ts` (+ `codyschneiderx/waterfall-gtm/processors/waterfall.py`). Provider ordering by `costPerCall / typicalHitRate`, short-circuit on confidence, `earlyExitOnConfidence`, canonical-key cache w/ TTL, and `onAttempt` telemetry. This *is* the Clay innovation in ~200 lines. Yupcha should make this the engine behind every enrichment column (email/phone/firmographics), with per-attempt cost + provider recorded on the cell for transparency.

2. **Build the email-finder waterfall + dual SMTP verification** → *enrichment waterfall*.
   Source: `tr4m0ryp/clay-enrichment/src/people/`. Pattern: Hunter domain-search (cache the *pattern* per company, 1 credit) → deterministic permutation → Gemini-grounded published-email → Prospeo, then verify via **port-25 RCPT probe with catch-all detection** *and* an **HTTP verifier fallback** (for cloud hosts where port 25 is blocked). Pair with `codyschneiderx`'s contact waterfall (Apollo→Hunter→Prospeo→Dropcontact→ZeroBounce). Directly lifts our email coverage and gives confidence/catch-all flags.

3. **Model the workbook column as a templated action engine** → *workbook UI + source engine*.
   Source: `eliasstravik/rowbound/src/core/` (`engine.ts`, `template.ts`, `condition.ts`, `extractor.ts`, `reconcile.ts`, `url-guard.ts`). Columns = HTTP/waterfall/formula actions with `{{row.x}}`/`{{env.key}}` templates, JSONPath extract, `ifEmpty` fallback, conditional runs, incremental reconcile, and an SSRF url-guard. Its **source types** (HTTP/exec/script/webhook + dedup + schedule) are a ready spec for "live lead-source engine" (the Workbook v2 direction in memory).

4. **Seed the copilot + AI columns with the Clay skill corpus** → *copilot / AI columns*.
   Source: `sachacoldiq/ColdIQ-s-GTM-Skills/master-skills/clay/`, `forma-norden/clay-claude-code-skill-pack` (`clay-ai-research-agent.md`, `clay-ai-column-prompts.md`, `clay-credit-optimization.md`), `resources/formulas/clayscript-library.md`. These encode how to write consistent AI-column prompts at scale, build research agents (our Claygent), and pick waterfall order for credit efficiency. Ship as built-in copilot skills + an AI-column prompt library.

5. **Add technographic + hiring-signal enrichment** → *enrichment waterfall / new columns*.
   Source: `rahulchhabria/local-enrichment-tool/src/lib/` — `tech-detector.ts` (13-category script-src/regex tech detection w/ confidence; no BuiltWith bill), `job-scraper.ts` (Greenhouse/Lever/Ashby ATS = hiring-surge signal), `linkedin-headcount.ts`, `github-fetcher.ts`. Gives Yupcha tech-stack and "is hiring" columns natively.

6. **A zero-cost research source for the copilot/source engine** → *source engine / copilot*.
   Source: `nilesh931/claygent-alternative/research_engine.py` — ddgs (no key) → crawlee-python (resumable, per-domain throttle, adaptive Playwright/HTTP) → trafilatura (clean extract) → SQLite, `fake-useragent` rotation. A $0 fallback research tier under the paid providers, and a resumable bulk-crawl pattern with built-in anti-bot UA rotation.

7. **Expand discovery beyond keyword search** → *source engine*.
   Source: `LeadGrowGTM/discolike-cli` (domain-similarity vector / ICP-text semantic / phrase-match search, `--auto-icp`). Plus first-party signal sources from `originaonxi/bre-gtm-engine` (SEC EDGAR, Companies House, planning permits, gov contracts, green finance) — vendor-free intent signals that differentiate Yupcha's source mix.

8. **Provider adapters + expose Yupcha steps as MCP tools** → *enrichment waterfall / integrations*.
   Source: `bcharleson/{prospeo,ocean-agent,leadmagic-agent}-cli` (clean `core/client.ts` adapters + the "one definition → CLI *and* MCP tool" pattern), `Othmane-Khadri/YALC/configs/providers/*.yaml` (Apollo/PDL/Crustdata/Pappers/Unipile schema set). Lets us grow the provider catalog fast and ship a Yupcha MCP so agents can drive enrichment.

9. **Add outreach-compliance gating** → *export / copilot*.
   Source: `originaonxi/bre-gtm-engine/compliance/` (`canspam.py`, `gdpr.py`, legitimate-interest-assessment). Before any export/send, gate on consent/legal-basis — a credibility feature Clay-style tools mostly lack.

10. **Workbook UX details + Clay feature-parity checklist** → *workbook UI*.
    Source: `clawnify/open-table` (drag-reorder columns, retype, debounced per-column filter, JSON row store, CSV export, `?agent=true` agent-mode UI) and `leszek-backpack/rex/action-registry.md` + `clay-api-reference.md` (exact Clay column/action schema to benchmark our column types and a possible "import from Clay" path).
